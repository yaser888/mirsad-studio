The work 01 / Capability

An agent that finishes the sentence.

Plan, act, observe, repeat. Mirsad keeps the loop grounded in real tool output — files read, commands run, tests passed — instead of confident prose. It stops at the step budget and reports what remains.

01 — LOOP

A loop that closes.

The model receives tool schemas, chooses actions, reads the results, and revises its plan. Duplicate calls are normalized. Cancellation leaves a valid transcript. The final answer is grounded in what actually happened.

The custody 03 / Security

Security is a posture, not a promise.

Mirsad does not claim to be unbreakable. It assumes the model can be wrong, the web can be hostile, and the machine can fail. Then it layers controls so no single mistake becomes the whole story.

Read the threat model →
Honest boundary: the agent runs with your desktop user permissions. Approvals and policy reduce blast radius; they are not a sandbox. The audit chain detects modification but is not an external notary.
  1. 01

    Risk-scored approvals

    Shell commands and file writes stop for review. The dialog names the action, its risk level, and the reasons. Destructive system commands are refused even after approval.

  2. 02

    Workspace boundary

    Every file and shell operation resolves inside the selected directory. Relative traversal, absolute escapes, and symlink escapes fail closed.

  3. 03

    DPAPI secret vault

    Provider keys are encrypted for the current Windows user. The interface receives set (****abcd), never the key. Vault operations are audited by name, not value.

  4. 04

    Hash-chained audit

    SHA-256 links make edits, reordering, and duplicate sequences visible. A cross-process lock keeps concurrent Studio and CLI writers on one valid chain.

  5. 05

    Secret-file guard

    .env, private keys, keystores, and credential files are blocked from reads, writes, edits, listings, and searches unless an operator deliberately overrides the guard.

  6. 06

    Hardened local shell

    The Studio loads only bundled local files. Remote navigation, new windows, plugins, persistent cookies, and local-to-remote access are disabled. External links leave through the system browser.

The ritual 04 / Workflow

Brief. Approve. Verify.

A deliberate loop, not an autonomous black box. You decide what the agent may touch, review the sharp edges, and leave with a record you can inspect.

01

Brief

Name the outcome. Mirsad inspects the workspace, builds a plan, and starts with reads and searches before it reaches for a write or a shell.

Plan → inspect → propose
02

Approve

Sensitive actions arrive with the exact command or diff, a risk level, and plain reasons. Approve once, deny, or stop the run. Denials are respected.

Review → decide → act
03

Verify

Tests, command output, and the audit chain tell you what happened. The session persists, so the work can be resumed or audited later.

Observe → record → resume

The install 06 / Begin

Bring your own instrument.

Mirsad runs on Python 3.10+ with PowerShell or bash. The desktop extra adds the native Studio. Provider keys stay on your machine; nothing calls home.

  • Windows 10/11 desktop
  • Python 3.10 or newer
  • OpenAI, Anthropic, OpenRouter, DeepSeek, Groq, or Ollama
  • No account required to run locally
